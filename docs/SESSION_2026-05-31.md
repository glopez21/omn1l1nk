## 2. Architecture Discussion (Key Points)

### Pipeline Flow
```
LogSentry ─┐
AlertFlow ──┤→ n3xuslib → omn1l1nk → n3xusDB → Augur
EventFlow ─┘
```

### n3xuslib — Redundant but Necessary?
- Thin library providing unified `N3xusClient.emit()` interface (HTTP POST or direct DB write)
- Critical feature: **SQLite offline buffer** in HTTP mode — without it, a network blip = permanently lost events on remote systems
- Without it, each agent would independently implement the same POST+buffer logic
- Verdict: Thin but essential for remote deployment resilience

### EventFlow vs LogSentry Overlap
- **LogSentry**: Security log ingestion → detection → alert generation
- **EventFlow**: General-purpose event streaming (CRUD, WebSocket, pub/sub)
- Different purposes but architectural boundary is unclear
- EventFlow needs PostgreSQL + Redis — fails on thin remote nodes

### NetWatch Redundancy
- Network monitoring could be a sub-service of Augur rather than a standalone project
- Deferred for later discussion

## 3. Remote Deploy System (In Augur)

### How It Works
1. Admin enters: server IP, API key (from omn1l1nk admin), node name in Augur's DeployModal
2. Generates one-liner: `sudo bash -c "$(curl -fsSL https://github.com/glopez21/n3xus-deploy/main/bootstrap.sh)" -- --server-ip <ip> --api-key <key> --node-name <name>`
3. Bootstrap script: preflight → install pipx → pipx install logsentry/eventflow/alertflow → create config → systemd services → smoke test

### Identified Issues

#### Critical: Wrong Default Port (8100 instead of 9000)
Three locations hardcode port 8100 but omn1l1nk runs on port 9000:

1. **`n3xuslib/n3xuslib/config.py:10`** — `endpoint: str = "http://localhost:8100"`
2. **`n3xus-deploy/bootstrap.sh:241`** — `ENDPOINT="http://${SERVER_IP}:8100"`
3. **`n3xus-deploy/bootstrap.sh:417`** — `os.environ.setdefault('N3XUSLIB_ENDPOINT', 'http://${SERVER_IP}:8100')`

This is almost certainly why the smoke test fails.

#### Other Issues
- **No asyncssh** — SSH deploy path in Augur backend fails with ImportError
- **Buffer flush stops on first failure** — one bad event blocks the queue
- **No retry backoff** — buffer flush retries every 30s flat
- **No HTTPS** — all traffic plaintext
- **EventFlow fails on thin nodes** — needs PG + Redis, service expected to fail
- **API key must be pre-created** — no automatic key provisioning in deploy flow

## Architecture Decisions

| Decision | Outcome |
|----------|---------|
| **LogSentry** | Universal log collector (security + all system logs) — keep and expand |
| **EventFlow** | Standalone generic event streaming — keep as separate entity |
| **AlertFlow** | Redundant with Augur's triage/incident capabilities — defer for audit |
| **NetWatch** | Should eventually be subsumed into Augur — defer |
| **n3xuslib** | Necessary for offline-buffer resilience on remote nodes — keep |
| **Pipeline** | agents → n3xuslib → omn1l1nk → n3xusDB → Augur |

| `n3xus-deploy/bootstrap.sh:417` | `8100` → `9000` (smoke test) |
